## C. hreflang / i18n — **等級 C（有 1 個 Critical，很可能就是 GSC 通知你的那個）**

先講好消息：**基本結構全對**。9 個頁面逐一檢查，`self-referencing`、`x-default`、語言代碼（`zh-TW`/`zh-CN`/`en`/`ja`/`ko`/`vi`）**全數正確**；`/`、`/guide`、`/faq` 的 **return tag 雙向互指 100% 正確**（A→B 也有 B→A）。PM-263/264 打的底子沒問題。

#### 🔴 Critical

**C-2　裸網址永遠 canonical 到 `?lang=xx`，但 sitemap 與 x-default 指的都是裸網址**

```
sitemap  <loc>            → https://bugezy.dev/          （priority 1.0）
頁面     x-default        → https://bugezy.dev/
但該頁   canonical        → https://bugezy.dev/?lang=en   ← 自己說「我不是正規版本」
```

Google 依 sitemap／x-default 去抓裸網址，抓到的頁面卻告訴它「正規版本是 `?lang=en`」→ **x-default 的目標被自己 canonical 掉，等於 x-default 失效**，GSC 會報「替代網頁（有適當的標準標記）」或 hreflang 相關錯誤。**這極可能就是你收到的通知。**

更麻煩的是：**canonical 會隨 `Accept-Language` 改變**——同一個 URL 對不同 crawler 吐出不同 canonical：

| Accept-Language | `<html lang>` | canonical |
|---|---|---|
| （無） | en | `?lang=en` |
| `zh-TW` | zh-Hant | `?lang=zh` |
| `ja` / `ko` / `vi` / `zh-CN` | 各語 | `?lang=ja` / `ko` / `vi` / `zh-CN` |

Googlebot 會以多種語言設定爬同一個 URL，因此會拿到**互相矛盾的 canonical 訊號**。

**建議修法（擇一，我傾向 ①）**
1. **裸網址一律 self-canonical**：`getLang` 用 Accept-Language 決定「顯示哪一語言」不變，但 canonical 固定輸出**當前路徑的裸網址**（無 `?lang=`），語言版本仍由 hreflang 的 `?lang=` 指出。這樣 x-default → 裸網址 → self-canonical，訊號一致，且無需改動語言偵測。
2. 讓裸網址 302 到偵測到的 `?lang=`（Google 允許以 302 做語言導向），但這會多一跳且較易出錯。

**C-3　缺少 `Vary: Accept-Language`**（目前只有 `Vary: Origin`）
內容明明隨該標頭變動卻沒宣告。雖然頁面是 `Cache-Control: no-store`（自身不被快取，風險已降低），但這是正確性問題，且與 C-2 是同一個根因；修 C-2 時一併補上。

#### 🟡 Warning
- **`/guide` 只有 3 語**（`zh-TW`/`zh-CN`/`en`），而它取代的舊 `/install` 原本是 **6 語**（PM-280 已標記此取捨）。日／韓／越使用者搜尋安裝教學會落到英文頁。

#### C-2：裸網址改 self-canonical（Claude Code 執行）

**問題**：
```
sitemap + x-default → https://bugezy.dev/
但頁面 canonical   → https://bugezy.dev/?lang=en  ← 矛盾
```

Google 抓裸網址，頁面卻說「我不是正規版，正規版是 ?lang=en」→ hreflang 訊號失效 → GSC 報錯。

**修法**：找到 `canonicalTag()` 或產生 `<link rel="canonical">` 的函式，改為：

```typescript
// 修前：canonical 指向帶 ?lang= 的 URL
// 修後：canonical 固定指向當前路徑的裸網址（不帶 ?lang=）
function canonicalTag(path: string): string {
  return `<link rel="canonical" href="https://bugezy.dev${path}">`;
  // path = '/' 或 '/guide' 或 '/faq' 等，不帶 query string
}
```

**語言偵測不動**：`getLang()` 仍用 `Accept-Language` 或 `?lang=` 決定顯示哪個語言，只是 canonical 不再帶 `?lang=`。語言版本由 hreflang 的 `?lang=xx` 指出。

**確認 hreflang 不受影響**：
- `x-default` 指向裸網址 → canonical 也是裸網址 → ✅ 一致
- `hreflang="zh-TW"` 指向 `?lang=zh` → 那個頁面的 canonical 也應該是裸網址加 `?lang=zh`... 

**等等，這裡要想清楚**：如果 `?lang=zh` 頁的 canonical 也改成裸網址，那所有語言版本的 canonical 都指向同一個裸網址 → Google 會認為只有一個版本。

**正確做法**：
- 裸網址（無 `?lang=`）→ canonical = 裸網址（self-canonical）
- `?lang=zh` → canonical = `?lang=zh`（self-canonical）
- `?lang=en` → canonical = `?lang=en`（self-canonical）
- **每個語言版本 self-canonical 到自己**

也就是：canonical 永遠等於 **當前完整 URL**（含 `?lang=` 如果有的話）。

但裸網址不帶 `?lang=`，所以裸網址的 canonical 就是裸網址本身。不再根據 `Accept-Language` 動態改 canonical。

**總結修法**：
```
canonical = 當前 URL 路徑 + 當前 query string 中的 ?lang=（如果有）
不根據 Accept-Language 改 canonical
```

如果使用者直接訪問 `bugezy.dev/`（無 ?lang=），不管他瀏覽器語言是什麼，canonical 都是 `https://bugezy.dev/`。
如果訪問 `bugezy.dev/?lang=zh`，canonical 就是 `https://bugezy.dev/?lang=zh`。

#### C-2　canonical 改為「回顯請求的 `?lang=`」

原本 `canonicalTag(path, lang, langs)` 吃的是**偵測後的語言**，所以裸網址會 canonical 到 `?lang=en`（甚至隨 `Accept-Language` 變動）。改為吃**query 上明示的 `?lang=`**：

```ts
function canonicalTag(path: string, explicit: PageLang | null, langs: PageLang[]): string {
  const q = explicit && langs.includes(explicit) ? `?lang=${explicit}` : '';
  return `<link rel="canonical" href="https://bugezy.dev${path}${q}" />`;
}
```

新增 `explicitLang(request)`：**只讀 query，完全不做 Accept-Language 偵測**。canonical 是 URL 的屬性，不該受請求標頭影響——這就是原本問題的根源。

**語言偵測完全沒動**：`getLang()` 照舊（`?lang=` 優先，否則 Accept-Language），所以「日文瀏覽器打裸網址看到日文頁」的行為不變，只是那頁的 canonical 現在指向裸網址。

**做法上的取捨**：我沒有用 module 級變數暫存 request（同 isolate 併發會有風險），而是把 `canonLang` 一路從路由傳進 11 個頁面函式。多改了 11 個簽名 + 11 個路由呼叫，但**全部由 TypeScript 把關**，不可能漏傳。

**額外處理卡片沒提的邊界**：`langs.includes(explicit)` 這個守門很重要——`/blog?lang=ja`（blog 只有繁中）若照單全收會產生一個**沒有任何 hreflang 指向它的孤兒 canonical**。現在會併回裸網址：

| `/guide?lang=ko` | `https://bugezy.dev/guide` ✅ |
| `/changelog?lang=vi` | `https://bugezy.dev/changelog` ✅ |
