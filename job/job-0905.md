## 🔴 第一次部署把首頁弄壞了，第二次才修好

上線之後抓 `bugezy.dev` 回來看，首頁 **Content-Length 只有 8013、沒有 `<body>`**，HTML 在這裡斷掉：

```
/* §2 hero（決策點 1）。⚠ 蜂巢紋 data URI 內不可有未編碼的
```

原因是我在 CSS 註解裡寫了 `` `;` `` —— **反引號提前結束了整個 template literal**。後面那半頁（三步驟、展示、賣點、語言帶、定價、CTA、footer）全部變成 dead code，從來沒有被回傳過。

**為什麼三道關卡全部沒擋下來**：

| 關卡 | 為什麼沒擋到 |
|---|---|
| `tsc --noEmit` | 反引號關掉字串之後，接著的 `;` 剛好結束 `return`，後面成了合法的 dead code —— 語法完全正確 |
| `wrangler deploy --dry-run` | 打包得起來就過，不會去執行頁面函式 |
| 280 條斷言 | 全部讀「原始碼字串」`srvRaw.includes(...)`，字串裡有沒有東西跟「這一頁真的長怎樣」是兩回事 |

**這是我這兩天第二次踩同一個雷** —— PM-435 的 FAQ 註解也寫過 `` `.faq-q.open + .faq-a` ``，那次 `tsc` 剛好報錯（`TS1109`）所以當場修掉；這次它沒報錯，就一路上了線。

### 補了兩層防線

1. **靜態護欄**（`_verify403` ⑰，3 條）：
   - 每個整頁樣板要在**自己這一段**裡收到 `` </html>` `` 終止符
   - 整頁樣板內的 CSS/HTML 註解不准有**未跳脫**的反引號
   - 開頭與終止符數量對得上（20 = 16 個多行 + 4 個字串串接）
2. **線上驗收腳本** `server/_verify-live.mjs`：部署後抓每一頁，檢查標記在、舊色碼不在、**收在 `</html>`**。靜態斷言永遠證明不了最後這件事，只有真的抓一次頁面作得了數。

護欄本身也反向測過 **5/5 全紅**（三種反引號寫法 + 弄丟終止符 + 把今天那個字元放回去）。過程中又抓到自己兩條假的：

- 「收得到終止符」是往後 `indexOf`，樣板壞掉時會撿到**下一頁**的終止符 → 永遠綠。改成限制在「下一個開頭之前」。
- 「`closes >= opens`」也永遠綠（整份檔案有 20 個 `` </html>` ``，多行 opener 只有 16）。改成兩邊都要等於 20。

另外原本想寫個會處理 `${...}` 巢狀的掃描器，結果被 `` ${post.description.replace(/"/g, '&quot;')} `` 裡的 **regex literal** 帶到檔尾（掃出 241 KB 的「樣板」）。手寫 JS 剖析器划不來，改成「開頭 → 終止符」的區間 + 只查註解，簡單而且正中失效模式。
