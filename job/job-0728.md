### 🟡 PM-263：全站 hreflang 標籤修復（解決 Google 多語頁面不索引問題）

**背景**：Google Search Console 通知「替代頁面（有適當的標準標記）」導致多語頁面無法編入索引。原因是缺少 hreflang 標籤，Google 不知道 `?lang=ja` / `?lang=ko` / `?lang=vi` 等是獨立語言版本。

**修法**：在 `server/src/index.ts` 的每個 HTML 頁面 `<head>` 中加入完整的 hreflang 標籤組。

**hreflang 標籤組**（每個頁面都要完整的一組）：

```html
<link rel="alternate" hreflang="zh-TW" href="https://bugezy.dev{path}?lang=zh" />
<link rel="alternate" hreflang="zh-CN" href="https://bugezy.dev{path}?lang=zh-CN" />
<link rel="alternate" hreflang="en" href="https://bugezy.dev{path}?lang=en" />
<link rel="alternate" hreflang="ja" href="https://bugezy.dev{path}?lang=ja" />
<link rel="alternate" hreflang="ko" href="https://bugezy.dev{path}?lang=ko" />
<link rel="alternate" hreflang="vi" href="https://bugezy.dev{path}?lang=vi" />
<link rel="alternate" hreflang="x-default" href="https://bugezy.dev{path}" />
```

其中 `{path}` 依頁面替換（`/` / `/features` / `/install` / `/faq` / `/changelog` / `/blog` / `/blog/{slug}` 等）。

**需要加的頁面**：

| 頁面 | 有多語版本 | 需加 hreflang |
|------|:--------:|:----------:|
| `/`（首頁） | ✅ 6 語 | ✅ |
| `/features` | ✅ 6 語 | ✅ |
| `/install` | ✅ 6 語 | ✅ |
| `/faq` | ✅ 6 語 | ✅ |
| `/changelog` | 中/英 | ✅（只列有的語言）|
| `/guide` | 中/英 | ✅ |
| `/blog` | 中文 | ✅（只列 zh）|
| `/blog/{slug}` | 中文 | ✅ |
| `/privacy` | 中/英 | ✅ |

**建議做法**：寫一個共用函數 `generateHreflangTags(path, availableLangs)`，各頁面呼叫時傳入支援的語言清單，避免重複代碼。

**同時修正 canonical 標籤**：每個語言版本的頁面 canonical 應該指向自己（不是主版本）：
```html
<!-- 日文版頁面的 canonical -->
<link rel="canonical" href="https://bugezy.dev/features?lang=ja" />
```

**wrangler deploy**

**改動檔案**：`server/src/index.ts`

**驗收條件**：
1. 首頁 6 語各有完整 hreflang 標籤組（curl 驗證）
2. /features、/install、/faq 同上
3. 每個語言版本的 canonical 指向自己
4. x-default 指向不帶 lang 參數的主 URL
5. /blog 等只有中文的頁面只列實際有的語言
6. `wrangler deploy` 成功
7. 用 Google Rich Results Test 或手動檢查 HTML source 確認標籤正確

完成後在下方寫 `🔵 DONE-263`。

### 🔵 DONE-263：全站 hreflang + 自我 canonical 已完成

**改動檔案**：只改 `server/src/index.ts`（已 `tsc --noEmit` + `wrangler deploy`，hash `38ae329f`）。

**根因確認**：各語言版本的 canonical 全部指向主 URL（如 `?lang=ja` 的 canonical 寫死 `https://bugezy.dev/features`）→ Google 判定 `?lang=ja` 只是主頁的「替代頁面（有適當的標準標記）」，因此不單獨索引。

**修法**：新增兩支共用 helper（放在 `ogMeta` 之後），11 個頁面各一行呼叫：
- `hreflangTags(path, langs)`：輸出該頁完整 hreflang 組 + `x-default`（指向不帶 lang 的主 URL）。**同頁所有語言版本輸出同一組**，滿足 Google 要求的雙向互指。
- `canonicalTag(path, lang, langs)`：canonical 指向**自己這個語言版本**（`?lang=<自己>`）；若該頁沒有此語言版本（例：`/blog?lang=en`）則收斂到主版本 `langs[0]`，避免產生不在 hreflang 組內的孤兒 canonical。
- 語言集合常數：`LANGS_6`（zh/zh-CN/en/ja/ko/vi）、`LANGS_3`（zh/zh-CN/en）、`LANGS_ZH`（zh）。

**各頁語言集合的判定依據**（依「實際有內容差異」而非「頁面存在」）：
| 頁面 | 集合 | 理由 |
|---|---|---|
| `/`、`/features`、`/install`、`/faq` | **6 語** | JA/KO/VI_MAP 已全譯（PM-233~235、PM-261）|
| `/changelog`、`/guide`、`/privacy`、`/skill`、`/feedback` | **3 語** | 走 `makeT`：zh 原文 + zh-CN 由 `toSimplified` 真實產生簡體 + en；**ja/ko/vi 會 fallback 英文故不宣告**（宣告了等於騙 Google）|
| `/blog`、`/blog/{slug}` | **僅 zh** | 文章正文不過 `t()`，各語言下內容相同（僅導覽列翻譯），依卡片「只列實際有的語言」|

**比卡片多做**：卡片表格未列 `/skill`、`/feedback`，但任務名是「**全站** hreflang」且這兩頁同樣有 canonical、也在 sitemap 內 → 一併加上（3 語），避免全站標記不一致。

**canonical 走 `?lang=zh`（而非裸 URL）的理由**：Google 要求 hreflang 指到的 URL 必須是該版本的 canonical。卡片提供的標籤範本本身即把 zh-TW 指向 `?lang=zh`，故 zh 版 canonical 也必須是 `?lang=zh`，六個語言 URL 才會各自 self-canonical 並構成完整叢集；裸 URL 保留為 `x-default` 入口。

**驗證**（curl 實測，腳本逐頁逐語檢查 hreflang 組合／canonical=self／x-default／alt URL 格式，**35 組全 PASS**）：
- 首頁 6 語、/features 6 語、/install 6 語、/faq 6 語 → 每個版本都有 7 條標籤（6 語 + x-default），canonical 各指自己。
- /changelog、/guide、/privacy 各 3 語 → 4 條標籤（3 語 + x-default）。
- /blog、/blog/vibe-coding-debug-trap → 2 條（zh-TW + x-default）。
- `/blog?lang=en` canonical 正確收斂為 `https://bugezy.dev/blog?lang=zh`。
- 原始 HTML 目視（`/features?lang=ja`）：canonical=`?lang=ja`、6 條 alternate + `x-default` 指向裸 `/features`，格式符合 Google 規範。
- /skill、/feedback 各 4 條 + canonical 指自己。

**驗收**：
1. ✅ 首頁 6 語各有完整 hreflang 標籤組
2. ✅ /features、/install、/faq 同上
3. ✅ 每個語言版本 canonical 指向自己
4. ✅ x-default 指向不帶 lang 的主 URL
5. ✅ /blog 等只有中文的頁面只列 zh（+ x-default）
6. ✅ `wrangler deploy` 成功（`38ae329f`）
7. ✅ HTML source 手動檢查標籤正確（見上）

**留給 PM（觀察，未動，超出本卡範圍）**：sitemap.xml 目前列的是裸 URL + 部分 `?lang=ja/ko/vi`，缺 `?lang=zh|zh-CN|en`。裸 URL 被 Googlebot（Accept-Language 空/en）抓時 canonical 會指向 `?lang=en`，仍在 hreflang 叢集內、不會產生孤兒，故**不影響本次修復生效**；若要讓 sitemap 全部列「canonical URL 本身」可另開一卡補齊。

### 🟡 PM-264：sitemap.xml 補齊所有語言版本 URL + wrangler deploy

**背景**：PM-263 修好了 hreflang，但 sitemap.xml 目前只列裸 URL + 部分 `?lang=ja/ko/vi`，缺 `?lang=zh`、`?lang=zh-CN`、`?lang=en`。Google 建議 sitemap 列出所有 canonical URL。

**修法**：

更新 `server/src/index.ts` 的 sitemap 生成邏輯，讓每個頁面列出**所有語言版本的 canonical URL**（跟 hreflang 一致）。

**規則**：
- 6 語頁面（`/`、`/features`、`/install`、`/faq`）→ 列 6 個 URL（`?lang=zh`、`?lang=zh-CN`、`?lang=en`、`?lang=ja`、`?lang=ko`、`?lang=vi`）
- 3 語頁面（`/changelog`、`/guide`、`/privacy`、`/skill`、`/feedback`）→ 列 3 個（`?lang=zh`、`?lang=zh-CN`、`?lang=en`）
- 僅 zh 頁面（`/blog`、`/blog/{slug}`）→ 列 1 個（`?lang=zh`）
- 裸 URL 保留（作為 x-default 入口）

**同時加入 sitemap 的 hreflang 擴展**（Google 支援的格式）：

```xml
<url>
  <loc>https://bugezy.dev/features?lang=zh</loc>
  <xhtml:link rel="alternate" hreflang="zh-TW" href="https://bugezy.dev/features?lang=zh"/>
  <xhtml:link rel="alternate" hreflang="en" href="https://bugezy.dev/features?lang=en"/>
  <xhtml:link rel="alternate" hreflang="ja" href="https://bugezy.dev/features?lang=ja"/>
  ...
</url>
```

如果 sitemap hreflang 擴展太複雜，可以只補齊 URL，不加 xhtml:link（HTML 裡的 hreflang 已經夠了）。

**wrangler deploy**

**改動檔案**：`server/src/index.ts`（sitemap 區塊）

**驗收條件**：
1. `curl https://bugezy.dev/sitemap.xml` 包含所有語言版本 URL
2. 6 語頁面各有 6 個 URL
3. 3 語頁面各有 3 個 URL
4. /blog 只有 zh 版本
5. `wrangler deploy` 成功

### 🔵 DONE-264：sitemap.xml 補齊所有語言版本 + hreflang 擴展 已完成
