## 那 GSC 到底在抱怨什麼？我查到了

寫了個腳本比對線上的 robots.txt、sitemap 與 11 個公開頁的連結：

```
① sitemap 裡有沒有被 robots.txt 擋住的 URL：沒有 ✅
② 公開頁面連到「被擋住」的路徑：
   /reports  ← 被 11 個頁面連結（/ /features /faq /guide …）
③ 被擋住的頁面自己怎麼標：
   /reports      200  <meta name="robots" content="noindex, nofollow">  |  無 X-Robots-Tag
   /report/:id   200  (無 meta robots)                                  |  無 X-Robots-Tag
```

**根因**：`/reports` 被**每一頁的 footer** 連結（PM-434 我把它放進共用 footer 之後變成全站 11 頁），同時又被 `robots.txt` 擋住 → Google 到處看到這個連結卻爬不進去 → GSC 就報「已封鎖 robots.txt，無法索引」。

而且這是 SEO 的**經典牴觸組合**：`/reports` 自己已經標了 `noindex, nofollow`，但 **robots.txt 擋著，Google 永遠讀不到那個 noindex** —— 所以它既不會被正確排除，又會一直出現在 GSC 的警告清單裡。

## 我做了什麼（保護性的部分）

**`/report/:id` 補上 `X-Robots-Tag: noindex, nofollow`。**
那頁原本**完全沒有 robots 標記**，只靠 robots.txt 擋。robots.txt 是「請不要爬」，不是「不要索引」—— 報告連結被貼到公開場合時，Google 仍可能把網址以裸連結形式收錄。加 header 之後就算哪天 robots.txt 改了也不會被索引。這個改動不會讓任何東西變成可索引，純粹是多一層保險。

## ⚠ 真正能消掉 GSC 警告的那一步，要你決定

三個選項，我的建議是 **A**：

| | 做法 | 結果 |
|---|---|---|
| **A（建議）** | 從 robots.txt 拿掉 `Disallow: /reports` | Google 爬得到 → 讀到 `noindex, nofollow` → **真正把它移出索引**，GSC 警告消失。該頁需要 token，沒 token 只會看到登入提示，沒有資料外洩風險 |
| B | footer 的 `/reports` 連結加 `rel="nofollow"` | 減少 Google 發現它的機會，但已經進 GSC 清單的不會自己消失 |
| C | 什麼都不做 | 警告會一直在。GSC 的「已封鎖」對**刻意封鎖**的 URL 本來就是資訊性的，不影響其他頁面的收錄 |

`Disallow: /report/`（分享報告）**我建議維持**，那是別人的資料，不該讓 Google 主動去爬。

## 🔴 收工前跑測試，發現「剛切過分支就會假紅」

`_verify403` 從 **232/0 變成 227/5**，而**程式碼一個字都沒改**。

原因：`git checkout`（PM-447 為了部署切去 master 又切回來）會依 `core.autocrlf` 把工作區
檔案寫成 **CRLF**，而斷言裡到處嵌著 `\n`：

```js
srvRaw.indexOf('`<!DOCTYPE html>\n')   // 找不到 → 整頁樣板數變 0
srvRaw.indexOf('\n}\n', ...)           // -1 → 切出來的 chrome 是空字串
```

五條紅的全是這一類（PM-434 的 nav/footer 選擇器、footer 色碼、`#pricing`，以及 PM-438
那條「整頁樣板要收在 `</html>`」）。**這種假紅最傷** —— 它會訓練人忽略紅燈，而 PM-438 那條
正是為了擋真正的頁面截斷而存在的。

**修法**：10 支會讀原始碼的回歸腳本，在入口把 `readFileSync` 包一層做 `\r\n → \n`，
既有的幾十個呼叫點一行都不用改：

```js
import { readFileSync as __rfRaw } from 'node:fs';
const readFileSync = (p, e = 'utf8') => __rfRaw(p, e).replace(/\r\n/g, '\n');
```

`_verify355` / `_verify366` 讀的是 `.gitignore`／`config.json`／memory 檔，沒有換行敏感的
斷言，不動。修完 `_verify403` 回到 **232 / 0 / 53 skipped**。
