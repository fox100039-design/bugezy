🔵 **DONE-404**

**🔴 這張卡有一個做不到的前提，我補了一條通道才做得下去**

卡片說記憶矩陣「透過 bridge MCP 的 `memory_stats` 取資料」。但 **bridge 與 Extension 之間的 WebSocket 協定是單向的**：bridge 送 `{id, command, params}`、Extension 回 `{id, ok, data}`，**Extension 沒有辦法主動問 bridge 任何事**。popup 想拿 `memory_stats` 完全無路可走。

如果照字面做，這個區塊會**永遠**顯示「Bridge 未連線」——連 bridge 明明連著的時候也一樣。那是在畫面上說謊。

所以補了一條 **Extension → bridge 的查詢通道**，並且刻意做窄：

| 設計 | 為什麼 |
|---|---|
| **硬編碼 switch 白名單**（目前只有 `memory_stats`） | 不是「查表找不到就拒絕」——新增能力**一定要有人動這段程式碼**，不會因為某個設定被改掉就多開一條路 |
| 🔴 **只放行唯讀查詢** | 這條通道打開的是「網頁旁邊的擴充功能可以呼叫 bridge」。破壞性操作（`memory_clear`）**不走這條路** |
| 未連線立刻回覆、不重試 | popup 只是要顯示一個數字，卡住比顯示「未連線」糟 |
| 5 秒逾時 | 同上 |

**因此 [清除全部] 按鈕我沒有做。** 卡片有列，但清空整層記憶是破壞性操作，走這條唯讀通道等於繞過 MCP 那邊的方案閘門與 `confirm: true` 防呆（PM-359 特地做的）。改成在區塊下方寫明：「要清除記憶請用 AI 呼叫 `memory_clear`」。**要我把它加上去的話，請先決定要不要為此放寬通道。**

---

**AI 監測：不是重寫偵測，是重跑同一組查詢**

`start_auto_detect` 本身在 bridge 裡（它是**編排**既有工具的呼叫序列，不含自己的偵測邏輯 —— PM-352 就是這樣定義的）。popup 沒有那條通道，但它編排的每一支底層工具 content script 都有。所以 `runScanAll` 依同樣順序問一遍 `map_page_zones` → `get_page_health` / `get_zone_health` / `get_browser_errors`，自己算出 Zone／Error／Score。

**沒有複製任何判定邏輯**：severity 來自 content script 已標好的欄位、score 直接用 `get_page_health` 算好的值。

結果下方固定附一句「錯誤只涵蓋最近約 30 秒；zone 為 0 時所有錯誤都會落在 Unassigned」—— **空結果的意思是「最近沒出事」，不是「沒問題」**，這句話不能省。

**記憶矩陣的三種狀態分開講**：未連線／連上但出錯／連上但 `.bugezy/` 還沒建立。混成一句的話使用者不知道要去修哪個。

**🔴 只加寬度修不好這個問題 —— 真正的原因是 flex 的預設行為**

卡片的第 1 點（加寬）是對的但不充分。實際情況是：**flex item 的 `min-width` 預設是 `auto`，空間不足時瀏覽器會先把文字折行，而不是讓它溢出**。所以「📌 圖釘（0）」旁邊擺一個「📌 釘選中... 點擊結束」（11 個字）時，兩者加起來剛好卡在 288px 內容寬度的邊緣——**時而正常、時而折行**，這也是為什麼它看起來像時好時壞。

三件事一起做才修得掉：

| 做法 | 少了它會怎樣 |
|---|---|
| `width: 320px → 360px` | 內容寬度 288 → 328，多出 40px 餘裕 |
| 標題 `white-space: nowrap` | 空間一緊還是會折行 |
| 按鈕 `flex-shrink: 0` | 換成按鈕被壓扁／截斷（把問題搬家而不是解決） |
| 標題 `min-width: 0` | flex 仍以內容寬度為下限，整列被撐開 |

**擠不下時的取捨是刻意的**：標題用 `text-overflow: ellipsis`，按鈕完整保留。驗收條件 2 要求按鈕不被截斷，所以要讓步的一定是標題那一側。

**三個 head 統一成同一種結構**（`.scout-head` / `.scout-block-head` / `.pin-head`）：flex row、標題左、按鈕右、`gap: 8px`。原本 `.scout-head` 只有 `gap` 沒有 `space-between`，`.pin-head` 則沒有 `gap`——三者行為不一致，改成一致的。
