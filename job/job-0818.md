### 🟡 PM-384：圖釘手動放置 — content script 釘選互動

**目標**：content script 進入釘選模式後，hover 元素高亮 + 點擊放圖釘。

---

**content script 側**（`extension/src/content.ts`）：

```
收到 PIN_MODE_ON：
1. 全頁 cursor 改為 crosshair
2. mousemove → 高亮 hover 的元素（藍色虛線框，用 highlightElement 共用函式）
3. 顯示 tooltip 在游標旁：元素的 tag#id.class（讓用戶確認要釘的是哪個）
4. click → 攔截（preventDefault + stopPropagation）
   - 算出該元素的唯一 selector（沿用 PM-309 的 computeUniqueSelector）
   - 彈出小輸入框讓用戶填描述（或跳過）
   - 呼叫內部的 pinElement 邏輯（跟 BRIDGE_PIN_ELEMENT 同一套）
   - 圖釘放好 → 顯示成功 toast
5. 按 ESC → 結束釘選模式

收到 PIN_MODE_OFF：
1. 移除所有釘選模式的 UI（cursor / tooltip / 高亮）
2. 恢復正常點擊行為
```

**關鍵細節**：
- click 必須攔截（否則會觸發頁面按鈕 / 連結導航）
- capture phase 攔截（`addEventListener('click', handler, true)`）確保最早攔到
- iframe 內元素不支援（跨域限制），hover 到 iframe 時 tooltip 顯示「iframe 內元素暫不支援」
- 釘選模式下右鍵不攔截（保留正常右鍵選單）

**驗收條件**：
1. 進入釘選模式 → cursor 變 crosshair
2. hover 元素 → 藍色高亮框 + tag tooltip
3. 點擊元素 → 圖釘放好 + 成功 toast
4. 點擊不觸發頁面原本的行為（連結不導航、按鈕不觸發）
5. ESC 結束釘選模式
6. iframe 元素 → 友善提示

完成後在下方寫 `🔵 DONE-384`。

---

🔵 **DONE-384**

**做了什麼**：釘選模式下 hover 高亮 + tooltip、點擊攔截並放圖釘、ESC 結束。

**最關鍵的一條是點擊攔截**：`click` 用 **capture 階段**攔（`addEventListener('click', h, true)`），並且 `preventDefault` + `stopPropagation` + `stopImmediatePropagation` 三個都下。少了攔截，使用者想「標記這個連結有問題」的動作會直接把頁面導走 —— 他標記的目標在下一秒就不存在了。已用真的 `<a href>` 加自己的 click handler 驗證：**連結沒有導航、頁面的 handler 一次都沒被呼叫**。

**沿用既有的東西，沒有重寫**：高亮用 `highlightElement`（PM-337）、selector 用 `uniqueSelector`（PM-309）、放圖釘走 `bridgePinElement`（跟 MCP 的 `pin_element` 是同一套，所以手動釘的圖釘 AI 立刻讀得到）。

**三個補上的邊界**
- **iframe**：content script 只跑在最上層框架，抓不到 iframe 內的元素。hover 時 tooltip 變橘色並說明「iframe 內的元素暫不支援（跨框架限制）」，點下去也只回 toast，不會假裝釘成功。
- **不能把 BugEzy 自己的 UI 釘起來**（圖釘層、面板、zone 覆蓋層）—— 卡片沒寫，但不擋的話使用者會釘到我們自己的圓點上。
- **右鍵不攔截**（卡片明訂），只有圖釘圓點自己的右鍵才攔（PM-387）。

**驗收對照**

|---|---|---|
| 1 | cursor 變 crosshair | ✅ 用 `CSSStyleSheet` + `html[data-bugezy-pin-mode]`，**不注入 `<style>` 字串**（Trusted Types 網站會擋，PM-69 的教訓） |
| 2 | hover → 高亮框 + tag tooltip | ✅ tooltip 顯示 `button#btn` 這種可辨識的形式 |
| 3 | 點擊 → 圖釘放好 + toast | ✅ |
| 4 | 點擊不觸發頁面原本行為 | ✅ 見上，用真連結驗證 |

### 🟡 PM-385：圖釘手動放置 — 描述輸入彈窗

**目標**：用戶點擊元素後彈出小型輸入框，讓用戶填寫圖釘描述。

---

**content script 側**（`extension/src/content.ts`）：

```
用戶點擊元素後：
1. 在點擊位置附近彈出 overlay 輸入框（shadow DOM 隔離）：
   ┌─────────────────────────┐
   │ 📌 描述這個問題（選填）    │
   │ ┌─────────────────────┐ │
   │ │                     │ │
   │ └─────────────────────┘ │
   │        [跳過]  [釘選]    │
   └─────────────────────────┘

2. 輸入框：
   - placeholder: '例如：這個按鈕點了沒反應'
   - 單行 input，按 Enter = 釘選
   - 自動 focus

3. 按鈕：
   - [跳過]：不填描述，直接釘選（description = 元素的 tag + text 摘要）
   - [釘選]：用輸入的描述釘選
   - 點擊彈窗外 = 取消（不釘選）

4. 釘選成功後：
   - toast 通知：「📌 已釘選 <button#submit>」
   - toast 2 秒後自動消失
   - 繼續留在釘選模式（可以繼續釘下一個）
```

**驗收條件**：
1. 點擊元素 → 彈出輸入框
2. 輸入描述 + 點釘選 → 圖釘帶描述
3. 點跳過 → 圖釘用自動描述
4. 點外部 → 取消
5. Enter 鍵 = 釘選
6. shadow DOM 不被頁面 CSS 干擾

完成後在下方寫 `🔵 DONE-385`。

---

🔵 **DONE-385**

**做了什麼**：點擊元素後在游標旁彈出描述輸入框（shadow DOM），[跳過] / [釘選] / 點外部取消 / Enter 送出。

**幾個細節**
- **shadow DOM + `adoptedStyleSheets`**：注入的是任意使用者的網站，一般 DOM 會被對方的 CSS reset 弄爛，我們的樣式也可能反過來汙染人家（PM-339 的結論）。全部用 `createElement`，**沒有一行 innerHTML**。
- **「跳過」不是不填描述**，而是用元素的自動描述（`button#submit「送出」`）。留空的圖釘之後在清單裡完全認不出是哪一個。
- **點外部取消用 `composedPath()` 判斷**：事件從 shadow DOM 冒出來時 `target` 會是 host，用 `target` 比對永遠不相等，會變成「點自己也取消」。
- **彈窗內按 ESC 只關彈窗，`stopPropagation` 不讓它往上傳**——否則按一次 ESC 會連釘選模式一起關掉，使用者只是想取消這一次輸入。
- **釘完留在釘選模式**，可以連續釘多個。
- 浮層會**夾在視窗範圍內**（`clampToViewport`），在右下角點擊時不會有一半跑到畫面外。

**驗收對照**
| # | 條件 | 結果 |
|---|---|---|
| 1 | 點擊元素 → 彈出輸入框 | ✅ |
| 2 | 輸入描述 + 釘選 → 圖釘帶描述 | ✅ |
| 3 | 跳過 → 自動描述 | ✅ 驗證含 tag 與元素文字 |
| 4 | 點外部 → 取消 | ✅ 且確認**沒有新增圖釘** |
| 5 | Enter = 釘選 | ✅ |
| 6 | shadow DOM 不被頁面 CSS 干擾 | ✅ |
