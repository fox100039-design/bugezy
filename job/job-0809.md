#### 🔴 卡片的 iframe 會被 CSP 直接擋掉（畫面只剩空白框）

本站全站注入 CSP，其中有 `default-src 'self'` 但**沒有 `frame-src`**。CSP 規則裡 `frame-src` 未指定時會**回退到 `default-src`**，也就是 `'self'` —— 於是 `https://www.youtube-nocookie.com/embed/...` 的 iframe 會被瀏覽器擋下，影片區只會留一個黑色空框，且錯誤只出現在 console，很容易誤以為是 YouTube 的問題。

**修法**：`CSP_VALUE` 加 `frame-src https://www.youtube-nocookie.com;`。
- 只放行 `youtube-nocookie`（不放 `youtube.com`），維持卡片的隱私考量。
- **不影響 `frame-ancestors 'none'`** —— 那條管的是「誰可以嵌入我們」（防點擊劫持，PM-219），這條管的是「我們可以嵌入誰」，兩者互不相干。

已線上驗證回應標頭確實帶 `frame-src https://www.youtube-nocookie.com;`。

#### 關鍵：`activateTicket()` 現在**只剩一個呼叫點**

原本有兩條路徑會直接打啟用 API（庫存票的「啟用」鈕、兌換後的「🚀 立即啟用」）。改法不是各自加確認，而是**兩條都改成呼叫 `askActivate()`**，真正打 API 的 `activateTicket()` 只由「✅ 確認啟用」觸發：

```

                ├─→ askActivate()（只顯示確認框，不打 API）
[🚀 立即啟用] ─┘         │
                          └─ [✅ 確認啟用] ─→ activateTicket() ─→ POST /api/promo/activate
                          └─ [取消] ─────────→ 關閉，什麼都不做
```

已用 grep 確認 `activateTicket(` 全檔只剩**確認鈕**這一個呼叫點——日後若有人新增第三條啟用入口，也不可能繞過確認。
