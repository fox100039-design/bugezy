### 🔴 卡片的診斷是對的，但根因比「自行加了 fallback」更具體 —— 那是我 PM-414 的 bug

`bee-video.js:110` 是這樣發事件的：

```js
if (!started) { started = true; this.dispatchEvent(new CustomEvent('bee-ready')); }
```

`this` 是 `<bee-video>` 元素，而 **`CustomEvent` 的 `bubbles` 預設是 `false`**。我在 PM-414 卻把 listener 掛在**父層** `.bee-stage`：

```js
document.querySelector('.bee-stage')?.addEventListener('bee-ready', …)
```

事件不冒泡 → listener 永遠不會被呼叫 → `beeFallback` 永遠不會被加上 `.hidden`。兩者都是 `position: absolute`、`<img>` 在 DOM 後面，所以那張靜態圖**從頭到尾就壓在 canvas 上**。你看到的「靜態在上蓋住動態」不是設計取捨造成的，是這個 bug 造成的。

我在 PM-414 的 DONE 裡寫「fallback 的方向是刻意反過來的：靜態圖預設就在畫面上，等 `bee-ready` 才藏起來」—— 想法沒錯，但那個「等」永遠等不到，等於直接把影片蓋掉。這條寫進註解留給之後：**真要補備援，listener 必須掛在 `<bee-video>` 元素本身，或讓那顆事件 `bubbles: true`。**

### 🔴 卡片有一條做不到：移除 `<input type="color">` 與 `<select>` 會讓整頁當掉

卡片說「現有 `<input type="color">` + `<select>` 改成 CSS 圓點和橫條」，同時說「`annotate.ts` 的 canvas 繪圖邏輯不動」。**這兩條互斥。**

`annotate.ts` 是這樣取元素的：

```ts
const $ = <T extends HTMLElement>(id: string): T => {
  const el = document.getElementById(id);
  if (!el) throw new Error(`missing #${id}`);   // ← 找不到直接 throw
  return el as T;
};
const colorPicker = $<HTMLInputElement>('colorPicker');
const lineWidthSel = $<HTMLSelectElement>('lineWidth');
```

拿掉任何一個，**模組初始化就 throw，整頁死掉** —— canvas、工具切換、語音全部不會啟動。而且繪圖時直接讀 `colorPicker.value` / `lineWidthSel.value`。

**所以兩個原生控制項都留在 DOM 裡當唯一真相**，視覺上照設計稿做：
- **顏色**：4 個色票（`#D92B2B` / `#14110B` / `#1E6FD9` / `#FFF4D6`）+ 最右邊一顆原生的「自訂顏色」。點色票只是把值寫進 `#colorPicker`。**保留自訂色是刻意的** —— 只給 4 色是功能倒退，標注工具本來就該能挑任意顏色；用自訂色時 4 個色票會一起取消選取，畫面不會說謊。
- **粗細**：3 條橫條寫值進 `#lineWidth`。那個 `<select>` 本來就只有 2/4/8 三個選項，1:1 對應。它收進 `.sr-only`（不是 `display:none`）**仍可鍵盤操作**，而且橫條的 `title` 直接抄對應 `<option>` 的文字 —— 那些 option 有 `data-i18n`，翻譯完就同步，不用另開 key 也不會有兩份文案對不上。

繪圖邏輯一行都沒動。

### 一件與卡片描述不符的事：`inject.ts` **沒有用 Shadow DOM**

卡片背景寫「`inject.ts` 65KB，Shadow DOM + CSSStyleSheet」。實際上這個檔案裡**沒有任何 `attachShadow` 或 `CSSStyleSheet`** —— 所有注入元件都是普通 DOM 節點掛在 `document.body` 上，樣式走 `style.cssText`。（用 Shadow DOM + `CSSStyleSheet` 的是 `content.ts` 的釘選 UI，PM-429 那張。）

這不影響改版，但影響一件事：**這些元件會繼承所在網站的 CSS**。所以我把每個元件的字體、字重、行高都寫死在 `cssText` 裡，而不是靠繼承 —— 否則在某些網站上字會被對方的全域樣式改掉。

### §3.4 三種字幕條：字級與**邊框強調程度**都分級

| 條 | 字級 | 邊框 | 為什麼 |
|---|---|---|---|
| 即時字幕 | **17px** | 1.5px 咖啡 | 使用者邊操作邊講，只會餘光掃過 |
| Whisper 錄音 | **16px** | 1.5px **黃** | 最強調 —— 這條在說「正在錄，講完要按停止」 |
| 鍵盤模式 | **16px** | 1.5px `--line-dark-2` | 最低調 —— 只是告知「語音關著」 |

三條邊框的強調程度是刻意拉開的：卡片只寫了顏色，但那三個顏色本來就構成一個「注意力階梯」，我把這個意圖寫進註解，並釘成斷言（否則下一個人很容易把三條統一成同一種邊框）。

### 狀態指示從「文字前綴 emoji」改成「獨立的標記」

即時字幕原本靠文字前面的 🟢 / ✅ / 🔴 表示狀態（`setCaptionText(\`🟢 ${trimmed}\`)`）。改成字幕條左側一顆**脈衝六角**，文字就是純文字。監控徽章同理 —— 六角做成文字的**兄弟節點**，因為 `updateMonitorBadge()` 會覆寫文字，放進去就會被洗掉（這次直接避開並釘成斷言）。

### §7.7 監控面板
