### 🔴 先講最重要的發現：那六處引用**一行都沒有渲染出來**

卡片說「6 處仍在引用，與大黃蜂色系衝突」。引用確實在，但**它們全部早就被 PM-416 蓋掉了**：

| 舊宣告 | 真正生效的 | 結果 |
|---|---|---|
| `#226 #stopBtn { background: var(--danger) }` | `#538 #stopBtn { … background: var(--y) … }` | 黃底 |
| `#227 #copyBtn { background: #2563eb }` | `#598 #copyBtn, #clearBtn { … background: transparent }` | 透明描邊 |
| `#228 #copyBtn.copied { background: var(--success) }` | `#604 #copyBtn.copied { background: var(--ink); color: var(--y) }` | 黑底黃字 |
| `#229 #exportBtn { background: var(--accent) }` | `#591 #exportBtn { … background: var(--ink); color: var(--y) … }` | 黑底黃字 |
| `#230 #exportBtn.done { background: var(--success) }` | `#597 #exportBtn.done { … }` | 咖啡底（本卡改黃底） |
| `#231 #clearBtn { background: #4a4a5e }` | `#598` / `#605` | 透明描邊 |

同為 `#id` 特異度、後定義者勝，所以**畫面上從來沒有出現過紫色或螢光綠** —— 這也是 PM-421 那 122 條護欄沒抓到它們的原因（護欄查的是「有沒有 emoji／有沒有 innerHTML」這類會影響畫面的事實，不是「原始碼裡有沒有死宣告」）。

`.scout-head`（`#342`）與 `.mode-toggle`（`#459`）同理：前者被 `body.dark .scout-head` 蓋掉，後者被 `.settings-body .mode-toggle { border-top: none }` 拿掉。

**所以我沒有照卡片「把這六行換成新色」——我把它們整段刪了。** 換色的話會變成「同一顆按鈕兩條規則、兩個顏色」，下一個人得先算 CSS 順序才知道哪個是真的。這正是這個 codebase 一路在避免的「兩個真相」。原地留了一段註解指向真正生效的位置。

`.scout-head` 與 `.mode-toggle` 的底線則是**改基準值**（不是刪）—— 它們在極端情況下還是可能生效（例如有人把 `.mode-toggle` 搬出 accordion），基準值本身就該是對的：第二層深底用 `--line-dark`、進階設定黃底用 `rgba(20,17,11,.2)`。

### ❌ `#stopBtn` 改磚紅這一項我沒有做

卡片第 1 點要 `#stopBtn` 從 `var(--danger)` 換成 `var(--err)`（磚紅 `#8A2A0F`），驗收也列了「`#stopBtn` 磚紅」。**我判斷這一項跟已經驗收過的規格牴觸，所以停在這裡等你決定**，其餘七項照做。

三個理由：

1. **設計稿畫面 03 明確畫的是黃底停止鈕** —— `background:var(--y); color:var(--ink)`。PM-416 的卡片自己也寫「停止按鈕（黃底）」，那張卡已經驗收過。
2. **§2.1 寫明 `--err` 的用途是「error / 5xx / 額度用盡」** —— 停止錄製是使用者主動完成一件事，不是錯誤。這套系統裡「要你做決定」的顏色是黃色（§2.2）。
3. **對比度會壞掉**：錄製中整頁是 `--ink #14110B`，磚紅 `#8A2A0F` 壓在近黑底上幾乎沉進去 —— 這正是 §2.4 反覆警告過三次的那類錯誤（深色系色票放到深底上沒有亮度差）。停止鈕是錄製中唯一的操作，不該是最不顯眼的東西。

我認為卡片第 1 點是在「把舊 token 換成新 token」的框架下做的機械對應（`danger` → `err`），而不是想改變停止鈕的顏色 —— 因為那六行本來就沒渲染，作者應該是看著原始碼而不是看著畫面寫的。**如果你真的要磚紅停止鈕，跟我說一聲，一行就改完；但那會同時要改 `#538` 並回頭修 PM-416 的驗收紀錄。**
