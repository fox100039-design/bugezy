§3技術架構 — bugezy-bridge（極速模式）
任何 AI（Claude / ChatGPT / Cursor / Gemini） │ MCP 標準協議 │ bugezy-bridge（localhost Node.js） │ Chrome Native Messaging │ BugEzy Extension（content.ts） │ 目標網頁
安裝方式
npm install -g bugezy-bridge

⚠ 這行不足以接通 Native Messaging，還需註冊 host manifest 與新增權限 —— 見 §12 A-3。

運作方式
  • bugezy-bridge 跑一個 localhost MCP server
  • 透過 Chrome Native Messaging 連接 Extension
  • AI 呼叫 MCP → bridge 轉發給 Extension → 拿結果回傳
  • 延遲 < 50ms
  • 全部在用戶電腦上跑，BugEzy 伺服器成本 = 0
§4技術架構 — 雲端模式（WebSocket）
任何 AI │ MCP 標準協議 │ Cloudflare Workers │ WebSocket（Durable Objects） │ BugEzy Extension │ 目標網頁
運作方式
  • Extension 啟動時建立 WebSocket 長連線
  • AI 呼叫 MCP → Workers 透過 WebSocket 推給 Extension
  • 延遲 ~200ms
  • 用戶零安裝成本

⚠ Durable Objects 需 Workers 付費方案，與「伺服器成本 = 0」有出入 —— 見 §12 A-4。

§12附錄 — 實作查證與待決策 ★新增

以下為撰寫規格時實際比對 server/src/index.ts、extension/manifest.json、cli/src 與現行方案設定的結果。§1~§11 是願景；這一節是動工前必須先知道的現實條件。

A-1　get_live_errors 已經存在，v2 的 getLiveErrors 是「另一條路」

現有 MCP 已有 get_live_errors，資料來源是 R2 上由 extension 即時監控寫入的快取（需 user_email + session_token），屬「非同步落地後再讀」。§5 規劃的是透過 bridge 直接向當前分頁要資料的同步路徑。兩者行為不同，不要當成同一個工具。

  • 方案 A：新工具改名（live_errors_now 等）並存 — 語意清楚，工具數量變多
  • 方案 B：get_live_errors 加參數 source: 'cache' | 'live'，bridge 可用走即時、否則退回 R2 — 使用者體驗較好，但要處理降級

建議方案 B（「AI 不需要知道 bridge 裝了沒」才是好體驗），但屬產品決策，留給 FOX 拍板。

A-2　工具命名慣例要先統一（PM-C 之前）

現有 13 個工具皆為 snake_case 無前綴（get_report_overview）；§5 新工具寫成 bugezy:camelCase。MCP 用戶端通常會自動以 server 名稱作命名空間，工具名再加 bugezy: 會出現 bugezy - bugezy:navigate 這種重複。

建議新工具沿用 snake_case 無前綴（navigate、read_page、analyze_element），文件裡的 bugezy: 只當說明用前綴。PM-C 之前定案，之後改名等於破壞相容性。

A-3　npm install -g bugezy-bridge 不足以接通 Native Messaging

除了裝 CLI，還必須：

  • 產生 native messaging host manifest（JSON：host 名稱、執行檔路徑、"type": "stdio"）
  • allowed_origins 填入擴充功能 ID — 本專案已用 manifest key 固定為 chrome-extension://hfnkjlbbpehkflgfbjenfmnmjkdjadcj/（PM-187 起）
  • 註冊到 OS 指定位置：
    Windows 登錄檔 HKCU\Software\Google\Chrome\NativeMessagingHosts\<host>
    macOS ~/Library/Application Support/Google/Chrome/NativeMessagingHosts/
    Linux ~/.config/google-chrome/NativeMessagingHosts/
  • Extension manifest 加 nativeMessaging 權限
⚠ 這會影響上架

新增 nativeMessaging 權限必然觸發 Chrome Web Store 重新審核，且要同步更新 Dashboard 與 /privacy（ARCHITECTURE §4-12、§4-15）。v1.1.5 已因權限問題被退件過一次。

→ PM-A 的範圍必須包含「安裝後自動註冊 host manifest」與「解除安裝時清除」，而不只是發一個 npm 套件。

A-4　Durable Objects 需要 Workers 付費方案

§4 的雲端模式以 Durable Objects 承載 WebSocket。DO 不在 Workers 免費方案內（需 Workers Paid，約 $5 USD/月起，另計請求與時長）。

與 §2「BugEzy 伺服器成本 = 0」有出入 —— 極速模式確實接近零成本，雲端模式不是。定價時要把這筆固定成本算進 Pro（雲端模式列在 Pro）。

A-5　現行還有「日票」與活動票券，§2 表格未列

v1 實際在賣：Free / NT$80 月費 / NT$20 日票（24hr），另有活動票券（兌換碼換免費天數，PM-265~267）。新分層上線時要決定它們對應哪一層（目前兩者都給「等同 Pro」的無限額度）。
